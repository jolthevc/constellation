# Research Desk
Research lives here when useful across multiple properties; property-specific notes can live under each property and link back to shared sources.

## Three states
1. **Question / candidate:** no evidence; list what to learn.
2. **Sourced observation:** dated URL, sample and limitations.
3. **Internal finding:** reproducible measurement/test in `performance/`; no causal claim from anecdote.

## Standard workflow
- Frame audience, format or commercial question before searching.
- Collect primary platform/publisher documentation first when researching policy, metrics or product functionality.
- Inspect multiple distinct creators and both high-performing and low-performing posts; avoid survivorship bias.
- Extract **mechanism** and original creative implication, not a clone of an existing account.
- Add source IDs to `sources.csv`, date/URL/caveats to each research brief, and propose an explicit experiment.
- Time-sensitive algorithm/policy claims need a next-review date; do not treat an old ranking explanation as a live guarantee.

## Folders
`competitive-intelligence/`: one competitor profile per notable property.
`trend-research/`: dated, expiring observations.
`platform-intelligence.md`: links and change detection.
`opportunity-backlog.csv`: research-stage ideas; not actual properties.

## Important boundaries
Never use private consumer information to profile individuals; do not infer sensitive attributes. Public content research is not a license to copy voice, likeness, scripts or creator identity. Store links and permitted notes rather than copyrighted media downloads.
